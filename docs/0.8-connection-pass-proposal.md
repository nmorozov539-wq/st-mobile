# 0.8 connection pass: proposal

Branch `0.8-connection-pass`, from `0.8-phase1-tokens` at `ac6aa4a`. This is an investigation only; no code has changed. It is based on reading Pocket's frontend and bridge, SillyTavern 1.19.0's own code (`/home/Riv/SillyTavern`, read only), and the 0.8.0-phase1 phone results.

## What you see today

With DeepSeek selected, after connecting and disconnecting:

- The model shows as `deepseek-flash`, and the engine says that model doesn't exist.
- Deleting a chat, choosing an alternative greeting and changing a preset all fail with "connect to DeepSeek first", even though none of them talk to DeepSeek.
- Failed changes pile up in **Review pending changes**. Its Reconnect button reloads the SillyTavern engine, which was fine all along, and nothing works there except Discard.
- After Discard, a preset toggle you made stays changed anyway.
- At the end, the same chat appears twice.

## The root cause: every save also re-selects the model

SillyTavern itself (the engine) was reachable the whole time. Only the model API (DeepSeek) wasn't. Pocket mixes the two up in one place.

Before any change to a chat or to settings, the bridge calls `activate()` and then `apply()` (`prototype/extension/workspace.js`). Making sure the right chat is open in SillyTavern is necessary; otherwise SillyTavern's own saves could overwrite the wrong file. But `apply()` also re-applies the chosen preset *and the chosen model*. When the model Pocket remembers differs from the one SillyTavern currently has, `apply()` calls `configuration.change({kind:'model'})`. For DeepSeek, that change only accepts a model from DeepSeek's model list, and that list is only loaded while connected (`extension/configuration.js`). So:

| What you do | Bridge path | Needs the engine | Needs the model API today | Should need the model API |
|---|---|---|---|---|
| Open a chat | `activate` → `apply` | yes | when the remembered model differs | no |
| Delete a chat | `mutate` → `activate` → `apply` | yes | same | no |
| Edit, delete or branch a message; choose an alternative or greeting | `mutate` → `activate` → `apply` | yes | same | no |
| Start a new chat, undo a delete | `newChat` / `undo` → `activate` → `apply` | yes | same | no |
| Preset entry toggle, generation values, scope, preset choice | `configure` → saves → `apply` | yes | same, but **after** the change is already saved | no |
| Character card, persona, World Info, Memory settings | their own writes, no `apply` | yes | no | no |
| Choose a model for a chat or character | `configure` (checks the loaded list) | yes | yes, the list must be loaded | only to offer the list |
| Send, another reply, Summarize now | generation | yes | yes | **yes** |

Character cards, personas and World Info were never blocked. The greeting that failed is the chat's first-message alternative, which is a chat change.

Your starting suggestion holds up against the code: saving local data needs only the SillyTavern engine, and only sending/generating needs the model. I found no real reason a save must select the model. The model only matters for the request a send makes, and the send path already checks the connection (`ensureApiConnection` in `app.js`).

## Why "deepseek-flash" appears

SillyTavern's built-in default DeepSeek model is the lower-case `deepseek-v4-flash` (`public/scripts/openai.js`, default settings and a migration rule). While disconnected, SillyTavern reports that default as the current model. Pocket shows it and copies it into its own saved global model choice (`syncGlobalModel`, and the global copy in `workspace.js`). After you connect, DeepSeek's real list uses different capitalisation, and SillyTavern picks the first listed model by itself. From then on Pocket's remembered name no longer matches the list, so every `apply()` tries to switch back to a name DeepSeek rejects: "not one of DeepSeek's models" while connected, and "Connect DeepSeek first" while not.

## Pending changes: what they do today

- Each chat or preset change is written to a journal on the phone (`frontend/journal.js`) and applied in order (`drain` in `app.js`).
- If applying fails for any reason other than "engine busy", the change is marked **conflict**, everything stops, and the recovery bar says "Pending changes need review".
- **Reconnect** reloads the engine frame. It cannot help when the engine is fine and the model API is the problem.
- **Resume** refuses while anything is in conflict.
- **Discard** only empties the journal on the phone. It never reverts anything.
- A preset change is stored *before* the failing `apply()`, so it was already saved. Discard just forgot about it, which is why the toggle stayed changed.
- While review is open, every other change is refused with "Reconnect and review saved changes first."

The journal exists for a real case: the engine reloading or the phone going to sleep in the middle of a write, so Pocket can tell whether a change landed. It was never meant for validation errors such as a model name, and it gives no way to fix the cause.

## The duplicated chat (likely cause; not reproduced)

Deleting a chat first switches SillyTavern to another chat. If that character has no other chat, SillyTavern creates a fresh one containing just the greeting (`mutate`, `deleteChat` in `workspace.js`). If a later step then fails, the delete still goes to review, which offers **Restore deleted chat**. Restoring brings back the original next to the fresh greeting-only chat. With a short test chat, the two look the same. I haven't reproduced this; the new tests below would cover it.

## Smaller items

- **"Turn off tool calling" on DeepSeek:** tool calling is a preset setting in SillyTavern, so applying a preset can switch it on. Pocket then refuses to send (`TOOLS_ENABLED` in `extension/runtime.js`) instead of just sending without tools. Proposal: Pocket switches tool calling off for its own sends, without blocking and without changing your preset. Small.
- **`--mock` doesn't start:** this is by design. A normal install refuses `--mock` ("This folder uses real-provider settings…"), because the mock needs its own separate install (`node prepare.cjs ~/SillyTavern ~/pocket-tavern-combined-test --mock`). Proposal: make the message say exactly which command to run, and mention it in PHONE-README. Small.

## Recommended new behaviour

1. **Saving never needs the model API.** Split `apply()` into two parts:
   - The *chat and preset* part: open the right chat and apply preset and generation values. It runs for every save and needs only the engine.
   - The *model* part: runs only before a send, another reply or Summarize. That is where "Connect DeepSeek first" belongs.
2. **Model names match the loaded list without caring about capitals.** When Pocket's remembered model is missing from the list, it says so in the model panel and offers the list. It never silently stores SillyTavern's default while disconnected.
3. **Pending changes shrink to a clear banner.**
   - Validation errors (bad model, invalid value, conflict with a newer change) fail immediately with a plain message. They are never queued.
   - Only a write cut off by an engine reload or timeout stays in the journal. It shows one banner, for example "Couldn't save *Delete conversation*: the engine restarted", with **Retry** and **Discard**.
   - Discard says plainly whether the change already landed.
   - The review dialog and its Reconnect button go away.
   - Other changes are no longer blocked while one is waiting.
4. **Delete without collateral:** don't create a replacement chat just to delete one. Leave the chat empty in SillyTavern's view, and only restore on Undo when the original is truly gone.
5. **Tool calling** is switched off for Pocket's own sends; **`--mock`** gets a clearer message.

## Rough size

- Items 1 and 2 (engine-only saves, model matching): **medium**. Mostly `workspace.js`, `configuration.js` and the send path in `app.js`.
- Item 3 (pending-changes rework): **medium to large**. It touches `drain`, the recovery bar, the review dialog and `journal.js`.
- Item 4 (delete): **small to medium**.
- Item 5 (tool calling, `--mock`): **small**.
- Overall: one focused pass, then a phone test with DeepSeek both connected and disconnected.

## Tests to add

- With the model API unavailable (DeepSeek list empty), each of these succeeds and never calls a model change: open chat, delete chat, edit, swipe, choose greeting, fork, undo, new chat, preset toggle, generation value, scope change.
- Send with the model API unavailable fails with the clear connection message and keeps the draft.
- The model part runs before send: Pocket's remembered model is selected, and a remembered `deepseek-v4-flash` matches `DeepSeek-V4-Flash` in the list.
- While disconnected, SillyTavern's default model is never written into Pocket's saved global model.
- A validation error is not queued: no journal entry, a clear message, and the next change still works.
- A write interrupted by an engine reload stays in the journal. Retry applies it once; Discard removes it and reports whether it had landed.
- Deleting a character's only chat leaves no extra chat behind, and Undo restores exactly one copy.
- A preset with tool calling switched on still sends, without tools, and the preset is unchanged.
- `start.cjs --mock` on a normal install prints the exact prepare command.
